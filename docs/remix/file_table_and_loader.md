# Smash Remix file ids and loader

Covers how Smash Remix 2.0.1 numbers the files it adds (`src/File.asm`), how its ROM and RAM are laid out, and how it loads files at runtime (`main.asm`, `src/Boot.asm`,
`src/Render.asm`), read from the source at `.toolchain/pkgs/smashremix-src` (commit `5e04fe7`). Port side: the Remix reloc table is extracted with the same ids
(`yamls/remix/reloc_*.yml`, generated by `tools/generate_yamls.py --version remix`, 5455 files from the reloc table at ROM `0x1AC870`), the code image is kept as the
`remix/ram_image` resource (`port/remix/remix_ram_image.{h,cpp}`, `docs/remix/torch_factories.md`), and `SSB64_DUMP_FILE_ID=<id>` dumps a decompressed reloc file for inspection.
The memory-map addresses below are the ones the 2.0.1 build produces (`build/remixasm/remix.sym`, made by `scripts/remix/assemble-remix.sh`).
Audit ledger (every item closed): `docs/remix/patch_audit.md`.

## Summary

- `src/File.asm` defines 3329 `File.*` constants: 8 vanilla ids (0x0591-0x0598, KIRBY_NSP_*) and 3321 Remix ids in 0x0854-0x154E.
- Remix ids are hard-coded constants. `File.asm` emits no bytes and nothing assigns ids at assembly time.
- The complete list of new ids (0x0854-0x154E, 3323 ids) is in `roms/filename_overrides.txt` (lines `HHHH Name`), one contiguous, strictly increasing block. Every one of
  the 3323 ids has a name there. 3321 also have a `File.*` symbol. The 2 without a symbol are 0x0FF6 and 0x0FF7 ("Marina Board the Platforms Header/Stage"); no code
  references them by name or number.
- Ordering rule (reproduces the table exactly): `id = 0x0854 + k`, where `k` is the zero-based index of the entry among the `filename_overrides.txt` lines whose id is
  >= 0x0854 (the file is sorted by id).
- Only one raw numeric Remix id is used directly in code: `0xC1B` (3099), in `Render.load_file(0xC1B, ...)` calls (`KirbyHats.asm:673`, `SinglePlayerModes.asm:5932`), instead
  of its symbol `File.REMIX_1P_KIRBY` (`src/File.asm:982`). The overrides name is "Remix 1p Kirby Stage File" while the code comments say "kirby hats remix"; treat the name as
  unconfirmed.
- Remix loader: `main.asm` places the code image at ROM 0x02C00000 (RAM base 0x80400000). `Boot.asm` `load_` DMAs it to RAM with `Global.dma_copy_` (0x80002CA0) at boot.
  Remix reloc-file loading goes through `Render.load_file_` (`Render.asm:921`).

## Looking an id up

There is no generated table in the repository; the sources are small enough to query:

```
# symbol -> id (File.asm line is `constant NAME(0xHHHH)`)
grep -n 'constant GND_USMASH(' .toolchain/pkgs/smashremix-src/src/File.asm
# id -> symbol
grep -n -i 'constant [A-Za-z0-9_]*(0x0*854)' .toolchain/pkgs/smashremix-src/src/File.asm
# id -> human name
grep -n -i '^0854 ' .toolchain/pkgs/smashremix-src/roms/filename_overrides.txt
# id -> file entry the port extracts (decimal file_id)
grep -n 'file_id: 2132$' yamls/remix/reloc_*.yml
# which source files use a symbol
grep -rn 'File\.GND_USMASH\b' .toolchain/pkgs/smashremix-src/src
```

The Remix label addresses (for example `Render.load_file_`, `file_table`) are in `build/remixasm/remix.sym`; `tools/n64_addr_to_symbol.py` resolves an address to a decomp or
Remix symbol.

## A. File id definitions

### A.1 How File.asm defines ids

- File: `src/File.asm`, lines 4-3336 inside `scope File { ... }`.
- Form: `constant NAME(0xHHHH)`. All 3329 constant lines match this form. Line 2845 (`CRASH_USPLanding`, 0x1364) is the only mixed-case symbol.
- Line 5 is the `// vanilla` marker, line 14 the `// remix` marker. Lines 6-13 are the vanilla KIRBY_NSP_* ids (0x0591-0x0598).
- Ids are sorted and contiguous from 0x0854 to 0x154E, except the 2 gaps 0x0FF6 and 0x0FF7 (no symbol). No duplicate ids or names.
- `src/File.asm` is included from `main.asm:24`, before `Boot.asm` and before every file that uses `File.*`.

### A.2 Where ids are consumed

- `src/Character.asm` `define_character(...)`: the file_1..file_9 arguments (for example `File.RANDOM_MAIN`, `File.RANDOM_CHARACTER`) become the 9 character-struct file id
  words (0x00-0x20) and the per-character file pointer slots. Of the 83 `define_character(` calls, none passes a raw Remix id literal. See `docs/remix/fighters.md` section 3.
- `Render.load_file(File.X, ptr)` (`Render.asm:549` macro), for example `Toggles.asm:396`, `Stages.asm:2831`, `Bonus.asm:23`.
- `custom_victory_file_table` (`SinglePlayer.asm:2304`) uses `dh File.SINGLEPLAYER_VICTORY_IMAGE_BOTTOM`, and so on.
- Raw ids (not names) used with `Render.load_file`: 0xC1B (above), plus many vanilla ids below 0x0854 (for example 0xC5, 0xE6, 0x153).

### A.3 Assignment mechanism

- Static: every id is a literal in `File.asm`. No `File.*` symbol is computed.
- Historical order: the ids were allocated sequentially in the ADD order of the injection tool (`build/master.csv`, mode ADD; first row 0x0854 `.\original\0854.bin`). The build
  tools (`build/readme.md`, `build/original/readme.md`) describe appending files in GE Editor and tracking them in CSVs. The overrides file preserves that order for all 3323 ids.
- Result: the ordering rule in the summary reproduces every id (3323 lines, 3322 steps of +1, no gaps, no duplicates, strictly increasing).
- `build/master.csv` (the older ADD manifest) lists only 359 new ids ending at 0x0A15, with gaps. It is stale; do not use it as the id source. `build/incremental.csv` has only an END row.

### A.4 Names

- Symbol names and overrides names differ in wording (for example 0x0854 `GND_USMASH` vs "Ganon upsmash"). Code uses the symbol; the overrides name is the human description.
- The port extracts files by id (`file_id` in the `yamls/remix/reloc_*.yml` entries), so a Remix `File.*` id is also the id the port passes to its reloc loader.

## B. Loader and memory map

### B.1 ROM layout (`main.asm`)

| ROM range | Source | Content |
|---|---|---|
| 0x000000 - end of vanilla | `main.asm:9-10` `insert "roms/original.z64"` | Vanilla SSB64 image (xdelta-patched) |
| 0x000020 - 0x000033 | `main.asm:13-15` | ROM name `SMASH REMIX` written over the internal name |
| 0x02C00000 - | `main.asm:18` `origin 0x02C00000`, `base 0x80400000` | Remix code and data image, assembled at RAM 0x80400000. Lies past the vanilla image. |
| 0x03000000 | `src/midi.asm:15` `MIDI_BANK` | Additional MIDI bank, grown through `MIDI_BANK_END` |
| `MIDI_BANK_END` onward | `src/FGM.asm` `write_sounds` (origins `*_extended_origin`) | Extended FGM parameter maps, bank table, predictors, raw samples, microcode. Entries are also patched inside vanilla ROM tables. |
| 0x03E7FFFF | `main.asm:337-338` `origin 0x3E7FFFF`, `db 0x00` | Pads the image to 0x03E80000 bytes (65 011 712; the comment on line 336 says "rom size = 64MB") |

### B.2 RAM layout (`main.asm` lines 325-334)

Code and data are assembled at RAM base 0x80400000 in this order (after all `include`s):

1. All `src/*.asm` code and data, from RAM 0x80400000 upward.
2. `midi_memory_block` (RAM `0x8058F760` in 2.0.1): `fill MIDI.largest_midi`, 16-byte aligned. Fixed block for music, replacing the vanilla MIDI allocation (`src/midi.asm:708`).
3. `file_table` (RAM `0x80599F20`): `fill 0x620` bytes, 16-byte aligned. RAM copy of the loaded-file list (B.4).
4. `custom_heap_address` (RAM `0x8059A540`): one word, initialized to `custom_heap`.
5. `custom_heap` (RAM `0x8059A544`): start of the dynamic heap. Everything from here up is free space.

Expansion RAM: `readme.md:14` requires the 8 MB expansion pak. The heap ceiling used in `src/TagTeam.asm:831` is 0x80800000 (`lui t1, 0x8080`), which matches an 8 MB pak mapped at
0x80000000-0x807FFFFF.

### B.3 Boot DMA (`src/Boot.asm`, scope `load_`)

1. `OS.patch_start(0x00001234, 0x80000634)` hooks the vanilla boot code: `j 0x80000438`.
2. `OS.patch_start(0x00001038, 0x80000438)` replaces the vanilla copy at 0x80000438:
   - `jal Global.dma_copy_` (vanilla DMA, a2=0x0100), original line kept.
   - `lui a0, 0x02C0` (ROM 0x02C00000), `lui a1, 0x8040` (RAM 0x80400000), `jal Global.dma_copy_` with `a2 = (((custom_heap - 0x80400000) >> 16) + 1) << 16`, that is the Remix image
     size rounded up to 64 KB. With `custom_heap = 0x8059A544` that is 0x1A0000 bytes (the source comment says 0x400000).
   - `j load_` jumps into the freshly copied image.
3. `load_` (the start of the Remix image code after the patch blocks) runs `SRAM.check_saved_`, then `Toggles.load_` or `SRAM.initialize_`, then returns to vanilla at 0x80000638.

The port keeps the whole 0x400000 range of ROM `0x2C00000` as `remix/ram_image` (`yamls/remix/remix.yml`), because Remix data tables and motion scripts are addressed by raw `0x804xxxxx`
pointers into it.

### B.4 Runtime file loading

- `Render.load_file(id, ptr)` (macro, `src/Render.asm:549`) sets `a0 = id`, `a1 = ptr` and calls `Render.load_file_` (`Render.asm:921`, RAM `0x804008DC`).
- `Render.load_file_` writes the id to `temp_file_ID`, calls vanilla `0x800CDEEC` (file length), allocates with `0x80004980` (malloc, 16-byte aligned), then calls vanilla `0x800CDE04`
  (load file into that buffer). The vanilla routines read the reloc table in ROM (Remix: 5455 entries at ROM `0x1AC870`).
- Loaded-file list: `Global.files_loaded` = `0x800D6300` (`src/Global.asm:210`). Format (`Global.asm:206-209`): word file id, word RAM address. `Render.asm:2228` and
  `SinglePlayer.asm:1804` read it.
- File manager struct: `0x800D62E0` (`LBInternBuffer`, `sLBRelocInternBuffer` in `decomp/src/lb/lbreloc.c`; used at `TagTeam.asm:1201`). `CharacterSelect.asm:1696-1699` writes `0x300` at offset
  0x1C (`status_buffer_max`) and `file_table` at offset 0x20 (`status_buffer`), so the vanilla loader tracks its loaded files in the RAM `file_table`. The unit of `status_buffer_max` is nodes
  of 8 bytes (id, address); the reserved block holds 0x620 / 8 = 196 of them, so the Remix capacity of 0x300 only matters if more than 196 files are tracked at once.
- `custom_heap_address` (RAM word) is the bump pointer for dynamic allocation. It is reset to `custom_heap` at `CharacterSelect.asm:2018-2020`, `GameEnd.asm:144-146` and
  `Render.asm:2457-2459` (mode select). `TagTeam.asm:806-833` moves it to expansion RAM when the default heap has been moved.
