## 0. Method and conventions

- Vanilla function of a patch = the function whose `// 0x8013xxxx` comment is the greatest value <= the patch address. A comment at line N belongs to the function at line N+1. Each entry shows `comment -> function (line)`.
- Remix RAM addresses come from `build/remixasm/remix.sym`. The `._return` label of a patch is always patch address + 8 (checked for P01 and P03), which is the instruction after the `j` and its delay slot.
- Confidence: H = name or asm comment confirms the function. M = only the comment-range rule. L = no comment covers the address.
- Line numbers in "AI.asm" are the lines of the Remix source.
- Routine IDs (section 1) were computed from the `add_cpu_input_routine` macro, not from comments. The comments are stale (see R-07).

## 6. Suspected asm bugs and risks (ranked)

1. P03 evade_fix_ (AI.asm 102-104): `t6 = 4` is set for the Remix 1P check, but the comparison uses `v1`. Possible dead auto-advanced AI in Remix 1P. Verify v1 on entry.
2. P22 TURNAROUND_WAIT (2446-2457): `beql` annuls the TurnRun delay slot, so `Action.TurnRun` is never detected. Real behaviour bug.

8. P04/P05: ordering and scope differences (P05 uses toggle only, P04 includes Remix 1P). Confirm intent.
9. P21 UNPRESS_C (`andi 0xFFF0`) clears more than the C bit (0x0001); P21 `cvt.w.s` rounds to nearest, the comment says truncate.
10. P17 runs on each custom-command return to 0x8013253C (the patch address is the same). Check it is harmless.
