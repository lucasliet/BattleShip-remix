## SFX replacement (ftremixsfxreplace.c)

- Toggle: none. `Toggles.asm` has no entry for SFXReplace (grep for `sfx`, `footstep`, `step` finds no relevant entry). The effect is always on for the scopes below. The port reads no toggle, the same as the asm.
- Screens (asm `_check_if_in_match`): VS battle 0x16, training mode 0x36, Remix modes 0x77 (Global.asm 81, 113, 122). The port reads `gSCManagerSceneData.scene_curr`.
- Stages (asm `_check_stage`): FLAT_ZONE 0x32 and FLAT_ZONE_2 0x62 (Stages.asm 76, 124). The port reads `gSCManagerBattleState->gkind`, the same source as the Remix camera code.
- Motion events: step table (23 ids, the last is 0x368, Bowser footstep) to `0x602` (snd_gaw_biip); landing table (12 ids) to `0x603` (snd_gaw_boop); hard landing table (7 ids) to `0x604` (snd_gaw_hardland).
- Down bounce: no screen check, stage check only (SFXReplace.asm:186-199). Every down bounce sound on a Flat Zone stage becomes `0x604`.
- The gaw ids come from `FGM.asm` 1832-1834 (`add_sound(sounds/misc/gaw_*)`). The port's bank was not checked for these ids. This is an open item for the game test.
- Deviation: none. Uncertainty: the asm tables use `dw 0` as terminator. The port uses `ARRAY_COUNT`, which is equivalent because no table holds 0.

## Color Overlays (ftremixoverlay.c)

- Toggle: `Toggles.asm:2382`, `entry_practice_overlay`, label "Color Overlays", default OFF. Read with `gmRemixToggle(practice_overlay)`.
- Struct mapping (struct_offsets.txt): `0x84` fp, `0x0D` `player`, `0x08` `fkind` (byte 0x0B = low byte), `0x24` `status_id`, `0x1C` `status_total_tics`, `0x14C` `ga`, `0x7EC` `damage_knockback_stack`, `0x18C` halfword mask 0x0480 = `is_reflect` (0x18C:5) + `is_absorb` (0x18D:0), `0xA68` `colanim.color1` (RGBA), `0xA88` bit 31 = `colanim.is_use_color1`.
- Hitstatus bytes: `0x05AF` = LSB of `special_hitstatus` (0x5AC), `0x05B7` = LSB of `star_hitstatus` (0x5B4), `0x05BB` = LSB of `hitstatus` (0x5B8). The asm subtracts 1 from each byte and ORs them; bit 0x2 is intangible (BLUE), otherwise GREEN.
- Hitstun counter `0x0B1A` (halfword) = low halfword of `status_vars.common.damage.hitstun_tics` (0x0B18, s32).
- Colours (asm values): RED 0xFF0000FF, YELLOW 0xFFFF00FF, GREEN 0x00FF00FF, BLUE 0x0000FFFF (Color.asm `high` scope), CYAN 0x00FFFFFF (literal in the asm, not in Color.asm).
- Priority per frame: toggle, reset last frame's colour bit, then vulnerability, then knockback (hitstun RED, or stop when the counter is 0), then reflect/absorb CYAN, then action (standing YELLOW without FAF; turn, light landing (0x1F, FAF 4) and heavy landing (0x20, FAF 8) YELLOW when status_total_tics >= FAF). Last, the ground flag is stored for the next frame.
- Turn FAF: fast (3) for Samus, slow (5) for the rest.

### Asm bug kept on purpose (Practice.asm:136-140)

The Falcon check compares `t0` (the fast FAF value 3) with the char id, not `t2` (the value 7 loaded for Falcon). The result: Falcon gets the slow FAF (5), not the fast one the comment describes. The port keeps the Remix build behaviour (`ftRemixOverlayTurnFAF`). Lead decision: keep this, or change Falcon to the fast FAF.

### Other notes

- The asm keeps the overlay flags in RAM across matches. The port keeps them in two file-local static arrays, indexed by `fp->player`, with the same lifetime.
- The asm writes only `color1`'s RGBA bytes, not the `ir/ig/ib/ia` increments. If a colour script left non-zero increments, the colour drifts while `is_use_color1` is set. The port does the same.
- Knockback test: the asm tests the raw f32 bits (`lw`), the port uses `!= 0.0F`. They differ only for -0.0, not expected in `damage_knockback_stack`.
- The Practice flash on Z-cancel is already ported in `ftremixzcancel.c` and is not touched here.

## What the lead must test in game

SFX replacement:
1. Stage: Flat Zone (or Flat Zone 2). Toggle: none, so there is nothing to set.
2. Modes: VS battle, training mode, and a Remix mode (all-star or multiman). Not expected in the menus or the Bonus stage.
3. Fighter: any. Expected: footsteps and running steps play the biip sound; landings play the boop; hard landings play the hardland sound. Down bounce (bounce off the floor after a hit) plays the hardland sound on Flat Zone.
4. Check first: the gaw sounds play at all. If they are silent, the port's FGM bank lacks ids 0x602-0x604.
5. Off the Flat Zone stages the normal sounds are back.

Color Overlays:
1. Menu: Miscellaneous, turn "Color Overlays" ON (default OFF).
2. Fighter: any; for the Falcon turn check use Captain Falcon and Samus.
3. Expected colours: YELLOW when actionable (standing after a grounded frame, turning, landing after the FAF). BLUE while intangible, GREEN while invulnerable (respawn or wall-bounce invincibility). RED during hitstun. CYAN with the reflect or absorb sphere up. No colour in other actions.
4. Falcon turn is slower than Samus turn (asm quirk above). Samus turn yellow at frame 3, Falcon turn at frame 5.
5. Turn it OFF: the tint must disappear and the fighter returns to normal colour within one frame.
