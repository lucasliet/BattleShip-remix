# T5.1: costumes, shades, D-pad variants and Random Select in the VS CSS

Sources: `src/Costumes.asm` (`select_`, `num_costumes`, `extra_costumes_table`), `src/Character.asm`
(`default_costume.table`, `variants.table`), `src/CharacterSelect.asm` (`get_character_id_`, `check_variant_input_`,
`get_random_char_id_`). Remix data tables are read from the RAM image by symbol (`REMIX_SYM_*`, generated by
`tools/gen_remix_actions.py`: `Character.default_costume.table`, `Character.variants.table`,
`Costumes.select_.num_costumes`, `Costumes.extra_costumes_table`). The image keeps u32 words in host order, so byte
tables are read through the word (`mnRemixCostumeReadByte`).

| Piece | Where | State |
|-------|-------|-------|
| Default costume row per fighter (4 C-button ids, red/blue/green team ids) | `ftParamGetCostumeCommonID/TeamID` read the image under `REGION_REMIX`, `mnremixcostumes.c` | done, all 97 fighters |
| C right/left cycle costume 0..max (wrap), C up/down cycle shade 0..2 | `mnPlayersVSUpdateCostume` + `mnRemixCostumeApplyButton` | done in VS; verified Mario (5 costumes) and Falco (6) |
| Costume-used denial removed (several players may share a colour) | `mnPlayersVSSelectFighterPuck`, `mnPlayersVSUpdateCostume` | done |
| D-pad variants (up special, down polygon, left J, right E), same direction again goes back | `mnremixvariants.c`, input in the VS cursor update, applied in `mnPlayersVSGetRemixPuckFighterKind` | done; verified Mario up = Metal, down = Polygon, left = J |
| Random Select setting (0 default, 2 all variants, 3 vanilla only) in the CPU random pick | `mnRemixRandomResolveFighterKind`, `mnPlayersVSRandFighterKind` | code only, not seen in a run (needs a CPU token) |
| L selects a random fighter (setting "'L' Selects Random Character") | VS cursor update, `mnPlayersVSRandFighterKind` | done; verified (Fox, Mario, Crash on three runs) |
| Variant fkind centred on the portrait of its base fighter | `mnPlayersVSRemixGetPortrait` | done |

Not done (left in the ROADMAP T5.1): extra costumes beyond `num_costumes` (the `costumes/*.asm` part tables and
`check_for_custom_costume_`), team-battle C buttons, variant D-pad icons and J/E flags, Z/R bonus bookend,
recent-randoms list. The 1P, training and bonus screens got the grid, costumes and variants in T5.1b (`f10_css_*.md`).

Bug found on the way: `grRemixCameraAdjustZoomRange` dereferenced `gSCManagerBattleState` before checking the screen,
so any fighter model made on the CSS crashed (NULL battle state). The stage is now read after the screen check.

## M11 Fase 4: what the VS CSS got next (2026-11-04)

Pure rules in `mn/mnplayers/mnremixcssrules.*` (tests `tests/remix/test_css_rules.c`), sprites in `mnremixcssindicators.*` and
`mnremixcssbonus.*`, hooks in `mnplayersvs.c`. Sprite offsets of file 0xA06 are checked against the `.o2r` by
`tools/test_remix_css_offsets.py` (309 offsets: the 97 portraits, names and logos, the bookends, D-pad, flags and variant icons).

| Piece | Where | State |
|-------|-------|-------|
| C buttons in team battle (`Costumes.asm disable_update`): they pick the costume only for a selected fighter whose token nobody holds; the shade kept in team battle (`0x80139A84`) | `mnRemixCssCostumeButtonsActive`, `mnPlayersVSCursorProcUpdate`, `mnPlayersVSCostumeSyncProcUpdate` | done, not seen in game |
| D-pad image, variant images, yellow mark and J/E flag of the panels (`update_variant_indicators_`, `draw_variant_icon_`) | `mnremixcssindicators.c`; the mark is an overlay rect (slots 34..37) | done, not seen in game |
| Bonus bookend: 10 fighters behind a bookend at the left of the grid, Z/R scroll (30 frames delay, then every 8), arrows and Z/R hint, flash, random pick pool with the bonus fighters when Random Select is not default | `mnremixcssbonus.c`, `mnplayersvs.c`, `mnRemixRandomPickFighterKind` | done, not seen in game |
| Handicap icons (values 10..40: stock icons, polygon, Metal, Master Hand, level bar) | `mnRemixCssMakeHandicapIcon`, hook in `mnPlayersVSMakeHandicapLevelValue` | display only; the arrows still stop at 9 (`REMIX-TODO(AI)`), so it never shows yet |

Not portable: the Random bookend and `recent_randoms_table`. The recent-random list only runs for the `?` placeholder
(`placeholder_port`, `CharacterSelect.asm 1327-1334`), which needs the RANDOM fighter (id 0x1B, `req/RANDOM_MODEL.req`) that the
port keeps unregistered (`remix_roster_data.h:31`); the L pick and the CPU pick do not touch the list.
Not ported either: `cpu_costumes_` (C buttons over a CPU panel change that CPU's costume, `Costumes.asm 1088-1160`).
