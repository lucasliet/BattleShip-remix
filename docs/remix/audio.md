# Smash Remix audio: banks (ctl/tbl/sbk), expansion and ROM map

Covers how Smash Remix 2.0.1 expands the N64 audio banks (read from `src/midi.asm`, `src/FGM.asm`, `src/BGM.asm`; source in
`.toolchain/pkgs/smashremix-src`), where the expanded data sits in `baserom.remix.z64`, the list of added tracks, and how the port
consumes it. Code: Torch factory `torch/src/factories/ssb64/RemixAudio*.{h,cpp}` (writes the o2r blobs), `port/bridge/audio_bridge.cpp`
(parses them), `decomp/src/gm/gmremixmusic*.c` and `port/remix/remix_music_titles_data.inc` (volume, titles; generated by
`tools/gen_remix_music_titles.py`).
Test: `tools/test_remix_blobs.py` (blobs against the Python reference `tools/remix_dump_audio.py`); in the game, a VS match with
`SSB64_AUDIO_DUMP_PATH` and `.toolchain/host/venv/bin/python -I .claude/skills/remix-smoke-tests/scripts/wavstat.py <run>`, `SSB64_AUDIO_FGM_LOG=1`
(ids >= 695 are Remix sounds), and `SSB64_START_SCENE=59` for the Sound Test.
Open gaps: `docs/remix/patch_audit.md`, group g9.

## 0. Summary: where the expanded banks are

| Bank | Pointer (table in ROM) | Vanilla ROM blob | Expanded data |
|---|---|---|---|
| Music instruments `B1_sounds1_ctl` | `0x3D75C` (`midi.asm:758`) | `0x252B560`, 0x6720 B | **Bank map moved to ROM `0x2C11170` = RAM `0x80411170`** (= `0x800472D0 + 0x3C9EA0`). The ALBank header pattern (`count=0x47`, 71 instruments) appears only at that address. |
| Music samples `B1_sounds1_tbl` | `0x3D760` (`midi.asm:762`) | `0x2531C80`, 0x116970 B | New instrument samples appended at `MIDI_BANK_END` (ROM `0x3000000` and up), `midi.asm:829-836`. |
| SFX `B1_sounds2_ctl` | `0x3D750` (`FGM.asm:238`) | `0x26485F0`, 0xFBA0 B | Extension at ROM `0x2C13200` = RAM `0x80413200` = `CTL_TABLE_PC(0x8004D9F0) + 0x3C5810`. |
| SFX `B1_sounds2_tbl` | `0x3D754` (`FGM.asm:240`) | `0x2658190`, 0x2DC1E0 B | New raw SFX at `MIDI_BANK_END` after the instruments, `FGM.asm:520-532`. |
| Sequences `S1_music.sbk` | `0x3D768` (`midi.asm:13`) | `0x2504750`, table 0x26E10 B | Entries 0 and 47..374 point to `0x3000000`..`0x330C710`. Entries 1..46 stay in the vanilla blob. |

The Remix offsets are relative to the ctl base **in RAM**, not to the file: the matching ROM address is RAM minus `0x7D800000` (code
segment: `main.asm:12-13`, `origin 0x2C00000` = `base 0x80400000`). Read as a file offset, `ctl+0x3C9EA0` lands in data that is not a bank.
The same applies to SFX: `ctl+0x3C5810` is `0x2C13200`, not a file offset. The first 4 KB of that block holds real values (for example
`003c5800 003c9510 003cb218 3f7e0004`), not `0xFFFFFFFF` placeholders.

Check: `0x2C11170` holds `0047 0000 0000 7d00 0000 2a90` (header of the 71-instrument bank), identical to the vanilla header except for the count.

## 1. How the Remix expands the banks at runtime

### 1.1 Music (bank 1 = music instruments)
- `midi.asm:758-762` reads the vanilla ctl and tbl (`0x3D75C`, `0x3D760`). `INST_CTL_TABLE_PC = 0x800472D0`.
- `midi.asm:923-949` (`move_instrument_bank_map`) copies the bank map (`OS.move_segment(INST_BANK_MAP, 0xB8)`) to `moved_inst_bank_map`
  in the code segment, appends `dw instrument_parameters_n - INST_CTL_TABLE_PC` for each new instrument, writes the count
  (`dh instrument_count + 1`) and points `ctl+4` at the new bank map. `instrument_count` starts at `0x2A` (`midi.asm:763`).
- Boot DMA: hook `OS.patch_start(0x20148, 0x8001F548)` (`midi.asm:1252-1254`) calls `jal 0x80002CA0` (vanilla dmaCopy) with
  `a0 = moved_inst_bank_map_origin` (ROM), `a1 = moved_inst_bank_map` (RAM), `a2 = 0x10 + instrument_count*4` (`midi.asm:1259-1264`).
  The bank map is DMAed from ROM `0x2C11170`, not from the `0x252B560` blob.
- Instrument samples (`add_instrument_sample`, `midi.asm:795-846`): raw data at `MIDI_BANK_END` (`midi.asm:829-833`), pointer
  `SAMPLE_RAW - INST_SAMPLE_DATA` (relative to the tbl at `0x2531C80`).

### 1.2 Sequences (tracks, S1_music.sbk)
- `MUSIC_TABLE` = the value at `0x3D768` (`midi.asm:13`). Header: `'S1'` (0x5331) at +0, `s16` count at +2 (**`0x0177` = 375 entries**,
  equal to the final `midi_count`), 8 byte entries from +4: `u32 offset` (relative to the sbk start) and `u32 size` (`midi.asm:95-98`).
- `MIDI_BANK = 0x3000000` (`midi.asm:15`) is the start of the extra space. `move_dream_land_midi` (`midi.asm:24-40`) moves Dream Land (id 0) there.
- Each track: `insert_midi` (`midi.asm:69-105`): `ID = (MUSIC_TABLE_END - MUSIC_TABLE)/8`, appends the entry to the end of the table
  (`MUSIC_TABLE_END`), inserts the `.bin` at `MIDI_BANK_END`, updates `dh midi_count` in `MUSIC_TABLE+2` (`midi.asm:108-109`) and
  `largest_midi` (`midi.asm:112-114`, used to size `midi_memory_block`, `main.asm:320-326`).
- Variants: `insert_external_midi` (`midi.asm:120`), `insert_midi` with 6 arguments and a toggle (`:177`), `insert_extra_midi` (`:184`, no
  title, order -1), `insert_named_extra_midi` (`:191`).
- Limits: ids are sequential from `0x2F` (47). There is no fixed-size table; the practical limit is the `s16` count and the ROM space
  (`main.asm:337`: `origin 0x3E7FFFF`, 64 MB ROM). Sound Test hooks that show the maximum number: `midi.asm:691-697` (`dh midi_count`, `midi_count-1`).
- Random music: `BGM.asm:278-327` and `BGM.asm:372` onward (random BGM tables, `fill 4*MIDI.midi_count`).

### 1.3 SFX/FGM (bank 2 = `B1_sounds2`)
- Base reads: `CTL_TABLE` = `0x3D750`, `RAW_SAMPLE_DATA` = `0x3D754`, `SFX_FGM_MAP` = `0x3D790`, `FGM_MICROCODE_MAP` = `0x3D798` (`FGM.asm:238-250`).
  Original constants: `ORIGINAL_FGM_COUNT=0x2B7`, `ORIGINAL_SFX_FGM_COUNT=0x1D0`, `ORIGINAL_SAMPLE_COUNT=0x142` (`FGM.asm:260-262`).
- Registration: `add_sound` (`FGM.asm:314`), `add_sound_advanced` (`:375`), `add_fgm` (`:426`), `reserve_fgm` (`:452`, unused). Each `add_sound`
  creates 1 sample, 1 SFX, 1 FGM and 1 Sound Test entry; `add_fgm` creates an FGM and a Sound Test entry, and an SFX only if `sfx_id == -1`.
- Registrations: `FGM.asm:989-1838`, closed by `write_sounds()` (`FGM.asm:1841`). After the macro, the `OS.patch` at `FGM.asm:945-951`
  adjusts the Sound Test (`0xF4 + new_sound_test_count`).
- `write_sounds()` (`FGM.asm:460-960`) writes, in order: `parameters_map_extended` (`0x10` per sample, at ROM `0x2C13200`, `:462-464`);
  `bank_table_extended` (`:466-487`); `predictors_extended` (`:490-510`, `0xA8` per block); raw samples at `MIDI_BANK_END` (`:520-532`);
  `sfx_fgm_table` (`:534-550`); `fgm_microcode` (`:552-568`); the voice map (`:571` onward); and updates the counts `SFX_FGM_MAP`
  (`dw 0x1D0 + new_sfx_count`, `:676-677`) and `FGM_MICROCODE_MAP` (`dw 0x2B7 + new_fgm_count`, `:680-681`).
- Volume and play hooks: section 4. Characters (for example `piano`, `FGM.asm:1180-1184`) use `.aifc` files from `src/<Character>/sounds/`; the raw
  data enters through the same `add_sound`.

### 1.4 Counts (static registration)

| Item | New | Id range |
|---|---|---|
| SFX samples (ALSound) | 815 | `0x8141`..`0x848F` (33089..33903) |
| SFX (sfx_fgm) | 824 | `0x1D0`..`0x507` (464..1287) |
| FGM (played audio ids) | 850 | `0x2B7`..`0x608` (695..1544) |
| Voice Sound Test entries | 850 | 244..1093 |

FGM `0x2B7` (695) is the first new one and is a placeholder in `FGM.asm:989`; `FGM.asm:962-974` treats `0x2B7` as SFX cancel, so the first new FGM
has special behaviour.

## 2. ROM layout

Every blob is **raw, uncompressed ROM**, outside the LBReloc file table (`yamls/remix/audio.yml`). The expanded data is in raw ROM ranges
(0x2C... and 0x30...), not in compressed reloc files. Extraction does not byte-swap; the endian conversion happens at load time in the audio bridge.

| Segment | ROM start | Size | Note |
|---|---|---|---|
| S1_music_sbk | 0x2504750 | 0x26E10 | table of 375 entries + vanilla 1..46 |
| new sequences (id 47..374) | 0x3001F40..0x330C710 | ~3.1 MB | entry 0 (Dream Land) at 0x3000000, size 0x1F3F |
| B1_sounds1_ctl (header) | 0x252B560 | 0x6720 | bank 0 points to 0x3C9EA0 |
| music bank map (new) | 0x2C11170 | 0x10 + 71*4 = 0x12C | boot DMA; RAM 0x80411170 |
| B1_sounds1_tbl | 0x2531C80 | 0x116970 | vanilla instrument samples |
| B1_sounds2_ctl | 0x26485F0 | 0xFBA0 | vanilla header |
| SFX extension block | 0x2C13200 | 0x10 * 815 = 0x3260 (start of the parameters map) | the other blocks follow at RAM 0x80413200+ |
| B1_sounds2_tbl | 0x2658190 | 0x2DC1E0 | vanilla raw |
| fgm_unk | 0x2934370 | 0x820 | `yamls/remix/audio.yml` |
| fgm_tbl (SFX_FGM_MAP) | 0x2934B90 | 0x2DD0 | |
| fgm_ucd (FGM_MICROCODE) | 0x2937960 | 0x4B20 | |
| end of the segments | 0x293C480 | | |
| new instrument and SFX samples | from MIDI_BANK_END after the 328 tracks | | order: tracks, instruments, SFX |

RAM to ROM in the code segment: `ROM = RAM - 0x7D800000` (checked at 0x80411170 to 0x2C11170 and 0x80413200 to 0x2C13200). The ctl offsets are
relative to the ctl RAM base (`0x800472D0` for music, `0x8004D9F0` for SFX), not to the file base.

The asm reads `roms/original.z64`, which is not in the repository; the values above come from `baserom.us.z64` and `baserom.remix.z64`. The
pointers `0x3D750`..`0x3D7A0` match between the Remix and the `read32` values of the asm.

Reading the banks from the ROM by hand: read the `S1_music` header and the 375 `(offset, size)` pairs at `0x2504750` (each entry at
`ROM = 0x2504750 + offset`). Music bank: read `0x2C11170` (`s16` count at +0, `u32` offsets at +0x10 relative to the ctl). SFX bank: ctl at
`0x26485F0` plus the extension at `0x2C13200`. The port gets all of this reconstructed, see `docs/remix/audio_extraction.md`.

## 5. How the port implements it

| Remix mechanism | Port implementation |
|---|---|
| Expanded ctl/tbl/sbk in ROM ranges | Torch factory `SSB64:REMIXAUDIO` (`torch/src/factories/ssb64/RemixAudioFactory.cpp`, `RemixAudioCtl.cpp`) rebuilds eight blobs from `baserom.remix.z64` into the o2r as `audio/B1_sounds1_ctl`, `B1_sounds1_tbl`, `B1_sounds2_ctl`, `B1_sounds2_tbl`, `S1_music_sbk`, `fgm_unk`, `fgm_tbl`, `fgm_ucd` (`yamls/remix/audio.yml`). The ctl is a RAM image (vanilla blob, then the code image at its RAM offset, zeros between), so the Remix offsets stay valid. The model is in `docs/remix/audio_extraction.md`. |
| Boot DMA of the bank map | Not needed: the reconstructed ctl already contains the Remix bank map. |
| Bank parsing | `BankParser` in `port/bridge/audio_bridge.cpp` parses the big-endian ALBankFile with bounds checks against the ctl blob size (`fits`), so the larger Remix ctl is accepted and a pointer outside it is rejected instead of read. Audio is disabled with an error log if the music or SFX bank does not parse. |
| Sequences | `parseSeqFile` points the sequence entries straight into the 14.7 MB sbk blob (it does not fit the audio heap and outlives the session). |
| FGM tables | `fgm_tbl` / `fgm_ucd` are rebuilt as compact tables (`BE u32 count`, offsets, records), `fgm_unk` as the flat envelope array; the bridge parses them as `SYAudioPackage`. |
| Track titles | `port/remix/remix_music_titles_data.inc` (generated), drawn at match start by `decomp/src/gm/gmremixmusictitle.c` (BGM.asm `show_music_title_`). |
| Stage music, random music (`BGM.asm`) | `grRemixGetStageBGM` (`decomp/src/gr/grremix/grremixstage.c`), the Random Music list (`grremixrandommusic.c`), master volume (`decomp/src/gm/gmremixmusic.c`), menu music (`gmremixmenumusic.c`). The custom MIDI entries of the Random Music list are not listed (their ids are assembly-time values without a symbol in `remix_symbols.h`). |

Case note for the Remix source: `main.asm:320` includes `src/MIDI.asm` and `FGM.asm:11` includes `MIDI.asm`, but the file is `src/midi.asm`. It builds
on case-insensitive file systems (macOS) and breaks on case-sensitive ones (Linux); `scripts/remix/assemble-remix.sh` runs on macOS.
