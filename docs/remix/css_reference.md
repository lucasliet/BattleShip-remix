# Smash Remix character select (CSS) reference

Covers the character select screens of the Remix (`CharacterSelect.asm`, `Costumes.asm`, `Teams.asm`, the CSS parts of the mode
files) and how the port implements them. Port code: `decomp/src/mn/mnplayers/` (`mnplayersvs.c`, `mnplayers1pgame.c`,
`mnplayers1ptraining.c`, `mnplayers1pbonus.c` and the `mnremix*` helpers), data in `port/remix/remix_css_data.h` (generated by
`tools/gen_remix_css.py`). The per-port option panel is in `docs/remix/panel.md`. Tests: `tests/remix/test_css_rules.c`,
`test_css_vsmodes_rules.c`, `test_css_cpu_costume_rules.c`, `test_teams_rules.c`, `test_twelvecb_layout.c`,
`test_twelvecb_custom.c`, `test_twelvecb_rules.c`, `.toolchain/host/venv/bin/python -I tools/test_remix_css_offsets.py` (309
sprite offsets of files 0xA05/0xA06 against the `.o2r`), and the in-game recipes of section 7.

Open gaps: `docs/remix/patch_audit.md`, groups g2 (CSS, costumes, teams, player tag) and g8 (12-Character Battle CSS).

Conventions: `CharacterSelect.asm:N` is `.toolchain/pkgs/smashremix-src/src/CharacterSelect.asm`; port paths are relative to
`decomp/src/mn/mnplayers/` unless a full path is given. Screen coordinates are N64 units (320x240).

## 1. Remix: grid, slots and tables

### 1.1 Layout

| Constant | Value | Source |
|---|---|---|
| `NUM_ROWS` x `NUM_COLUMNS` | 3 x 10 | `CharacterSelect.asm:3570-3574` |
| `NUM_SLOTS` | 30 | `:3599` |
| `START_X`, `START_Y`, `START_VISUAL` | 29, 34, 10 | `:3575-3590` |
| `PORTRAIT_WIDTH` x `PORTRAIT_HEIGHT` | 24 x 24 | |
| `PORTRAIT_SCALE` | 0.8125 (`0x3F50`) | portraits are 32x32 images |
| `BOOKEND_WIDTH` | 15 | |
| `BOOKEND_BONUS_PORTRAIT`, `BOOKEND_RANDOM_PORTRAIT` | 30, 31 | portrait numbering past the grid |

Grid (`scope layout`, `:3600-3635`), the cell of slot `s` is at `(10 + 29 + 24 * (s % 10), 10 + 34 + 24 * (s / 10))`:

- Row 1: Marina, Dr. Mario, Luigi, Mario, Donkey, Link, Samus, Captain, Ganondorf, Sonic.
- Row 2: Dedede, Young Link, Ness, Yoshi, Kirby, Fox, Pikachu, Jigglypuff, Falco, Sheik.
- Row 3: Goemon, Crash, Wario, Peach, Bowser, Wolf, Conker, Mewtwo, Marth, Banjo.

Bonus bookend (`bonus_chars`, `:23-35`, `NUM_BONUS_CHARS` 10): Dark Samus 0x22, Lucas 0x26, Peppy 0x42, Slippy 0x43, Roy 0x4A,
Dr. L 0x4B, Lanky 0x4C, Dragon King 0x47, Ebisumaru 0x46, Piano 0x36. The scroll index is kept per port and per mode
(`bonus_char_index_vs/1p/training/bonus`, `:39-62`). `Character.NUM_CHARACTERS` is 97 (`Character.asm:15-27`); only the 30 grid
fighters, the 10 bonus fighters and Random are selectable, the rest are reached through D-pad variants.

### 1.2 Tables indexed by `Character.id`

All are 4 bytes per id, padded to `NUM_CHARACTERS * 4`.

| Table | Maps | Asm |
|---|---|---|
| `id_table` | grid slot to `Character.id` | `:3914-3927` |
| `portrait_offset_table` | grid slot to portrait offset in file 0xA05 (plus the two bookends in file 0xA06) | `:3930-3945` |
| `portrait_id_table` | id to portrait index; special cases for the polygons, Metal Mario, Giant DK, the Master Hand, the placeholder and NONE | `:3982-4024` |
| `name_texture_table` | id to name texture offset in file 0x11 | `:3533-3565` |
| `series_logo_offset_table` | id to emblem offset in file 0x14 | `:3401-3433` |
| `selection_action_table` | id to the demo status the confirmed fighter plays | `:2998` |
| `white_circle_size_table` | id to spotlight scale | `:3033` |
| `fgm_table` | id to announcer FGM | `:3565` |
| `variants.table` (`Character.asm:2524-2563`) | id x 4 D-pad variants (up special, down polygon, left J, right E) | |
| `default_costume.table` (`Character.asm`) | id to 4 costume ids (one per C button) + red/blue/green team costume ids | |

Names and offsets of the Remix-only fighters carry a `+0x10` that points past the 16-byte image header (`:3437`); the generator
applies it.

### 1.3 Files

| File id | Content |
|---|---|
| 0xA05 (`CHARACTER_PORTRAITS`) | 97 portrait images, 32x32, offsets from `CharacterSelect.asm:3075-3170`; the white flash image of a portrait is at its offset + 0x860 |
| 0xA06 (`CSS_IMAGES`) | bookend images (bonus 0x3B28, Random 0x53E8), D-pad (0x218), variant flags J 0x558 and E 0x3B8, polygon icon 0x13A8, panel menu buttons (0x1208, 0x1828), team buttons |
| 0x11 (`MNPlayersCommon`) | vanilla names, Remix names (`CharacterSelect.asm:3437-3530`), arrows (`ArrowL` 0xECE8, `ArrowR` 0xEDC8), the 12CB RESET button (0x187A8) |
| 0x14 (`FTEmblemSprites`) | vanilla and Remix series logos (`series_logo.offset.*`, `:3184-3400`) |
| 0x12 (`MNPlayersGameModes`) | mode title images (section 5) |

Asm rows 1088, 1099, 1110 and 1121 write 0 over the file id of the vanilla portrait file 0x13 on the four CSS: the Remix never
loads it.

## 2. Remix: behaviour

### 2.1 Cursor, token and hit test

- A token is selected by the position of the token, not of the hand: `get_character_id_` (`:449-480`, one hook per mode). It reads
  the per-mode CSS player struct (`CSS_PLAYER_STRUCT` 0x8013BA88, `_TRAINING` 0x80138558, `_1P` 0x80138EC0, `_BONUS` 0x80137620).
- Normal grid: `y < 72` after subtracting the grid top, `x < 240`; `column = x / 24`, `row = y / 24`, `index = row * 10 + column`
  (`:520-554`). A token left of the grid (`x < 0`, down to `-15`) is over the bonus bookend, right of it over the Random bookend.
  A token held at y 85 with the cursor in pointing state selects nothing.
- Tokens are drawn at scale 0.8125 (`adjust_created_token_`, `adjust_changed_token_`, `adjust_scaled_token_position_`,
  `:809-920`; not in the 12CB) and follow the hand at +12/-10. `token_autoposition_` (`:649-760`) centres a placed token on its
  cell (`START_X + 12`, `START_Y + 12`). `fix_right_boundary_check_`, `fix_bottom_boundary_check_` (`:949-980`) include the
  bookends. The cursor stops at y 212 instead of 205 so the bottom rows of the panel menu and the 12CB RESET are reachable
  (`:992-1004`). The overlap check compares portrait ids (variants of one portrait repel each other) and the VS overlap radius is
  10 instead of 15 (`:1011-1076`). On the 1P and Bonus screens the token does not drift towards the cell interior
  (`:1826-1833`).
- Master Hand: the Link up variant is allowed only when the 20th custom player tag is not blank (`:451-479`, `:1130-1138`).

### 2.2 Random

- `get_random_char_id_` (`:1128-1170`): pool is the 30 grid slots, plus the 10 bonus fighters when the Random Select setting is not
  Default. Setting values: 0 Default, 1 Bonus, 2 All variants (one pick in five turns into one of its four variants), 3 Vanilla
  only (rerolls non-vanilla fighters).
- Anti-repeat (`:1320-1342`): `recent_randoms_table`, `RRL_NUM_SLOTS` 6 per port. A fighter rolled again within the list is kept
  with probability 1/matches. It only runs for the Random token (`placeholder_port`), not for the L trigger or the CPU pick.
- Random token: the Random bookend (right of the grid) accepts a token; `save_random_char_` (`:6679-6699`) rolls a fighter when
  the screen is left, `load_random_*` (`:6960-7000`) puts the `?` token back when the screen is entered again. In team battle
  the rolled fighter's shade avoids a teammate holding the same fighter (`_teams_loop`).
- `'L' Selects Random Character` (setting): L over a held token rolls a random fighter (`check_variant_input_._vs`).

### 2.3 Costumes, shades, variants

- `Costumes.asm select_` (`:621-643`): C right/left step the costume id through `0..num_costumes` with wrap (extra costumes of
  `extra_costumes_table` included), C up/down step the shade 0..2. A fighter with 0 costumes keeps costume 0 and still cycles
  the shade. The "costume already in use" denial is removed (`:1284-1304`).
- `disable_update` (`:1051-1069`): in a team battle the C buttons change the costume only of a selected fighter whose token nobody
  holds; the shade is kept in team battle.
- `cpu_costumes_` (`:1098-1103`): C buttons pressed with the cursor over a CPU panel change that CPU's costume (VS and Training).
- `get_default_costume_` (`:1945-1985`) reads `Character.default_costume.table` for the C-button and team costume ids.
- D-pad variants (`check_variant_input_`, `:2365-2390`): while a token is held, D-pad up/down/left/right set the variant slot of the
  portrait under it (stored in `variant_offset` per port, `:2720`); the same direction again goes back to the normal fighter.
  `variants.table` is filled only for the vanilla fighters and a few Remix ones; a fighter without an entry has no variant.
- Variant indicators (`update_variant_indicators_`, `draw_variant_icon_`, `character_change_` `:4828-4846`): a D-pad image next to the
  panel, the variant fighters' icons around it (J/E flag by variant type, polygon icon, or the variant's stock icon), a yellow mark
  on the active direction.

### 2.4 Bookends and slide-in

- Bonus bookend: a 15 x 72 image left of the grid (x 24, y 44). With the token on it, Z or R scroll the 10 bonus fighters (first
  press at once, then every 8 frames after a 30-frame delay, wrap at both ends, Z wins when both are held). The scroll is an index,
  not an animation; the chosen fighter appears as the token fighter.
- Random bookend: x 279, same top and size; a token dropped on it is placed at (278, 70).
- `draw_portraits_` (`:3606-3862`): every portrait and both bookends slide in from outside the screen (x -20 for the left columns,
  310 for the right ones) at a speed per column, `portrait_x_position`/`portrait_velocity` (`:3878-3912`, 12 entries); the patched
  animation routine is at 0x80131DC8.
- The white flash when a token lands (`set_white_flash_texture`, `:1614-1676`) is the 32x32 flash image at the portrait offset +
  0x860 in file 0xA05, scale 0.8125, at the portrait position. In Remix 2.0.1 that image holds the same picture as the portrait
  (texels dumped in the port), so nothing visible blinks: the reference capture `build/ref-shots/css_flash` (frames 2336-2358 of
  `scripts/ref-emu/inputs/vs_match.txt`) shows no cell changing while the two tokens land.
- Defaults (`:1082-1121`): the vanilla portraits, shadows and fire background are not loaded or drawn.

### 2.5 Model, spotlight, announcer, name and emblem

- `get_name_texture_`, `get_series_logo_offset_` read the tables of section 1.2 (`:1710-1810`); an offset of 0 draws nothing.
- `get_zoom_` (`:1843-1894`) is the spotlight scale (`white_circle_size_table`), `get_action_` (`:1911-1929`) the demo status of the
  confirmed fighter, `get_fgm_` (`:2228-2261`) the announcer voice.
- Model loading: `load_character_model_` (`:77-134`) loads only the main and model files through an alternate req list, preloads
  all of them (`load_additional_characters_`, `:1985-2005`) on a custom heap (`dynamic_css`, `:4081-4290`, `increase_heap_`). This
  exists only to fit N64 RAM.

### 2.6 Modes on the VS CSS

`TwelveCharBattle.asm`, `TagTeam.asm`, `Smashketball.asm`, `KingOfTheHill.asm`, `TugOfWar.asm` and `VsRemixMenu.asm` patch the VS
CSS (hooks `mode_specific_setup_`, `_returning_`, `_start_`):

- **Header image and announcer** (`update_css_header_`, `update_announcer_on_entry_`): offsets in file 0x12 of the mode title
  (12CB 0x2048, Tag Team 0x2738, King of the Hill 0x29A8, Smashketball 0x2C18 for type 1 and 0x2E88 for type 2, Tug of War
  0x30F0) and the announcer FGM (12CB 1016, Tag Team 783, King of the Hill 775, Smashketball 776, Tug of War 479). Toggling
  Free-for-all/Team keeps the mode title (the asm patches the title table 0x8013B7C8 for both slots). A finished 12CB announces
  "Player N" (FGM 503/504) then "Wins" (533) at frame 0x34.
- **Goal picker** (`Smashketball.asm use_goal_yellow_picker_`, `CharacterSelect.asm check_picker_press_` `:6290-6400`): in King of
  the Hill and Smashketball the time/stock picker is the yellow "GOAL" picker (image offset 0x27FC8 instead of 0x48B0); a press on
  it toggles between the goal and the VS Time. Tag Team and Tug of War (rule Timed Stock) get a stock to Time toggle. The press
  ignores a held A. `showing_time` is reset by `mode_specific_setup_`.
- **VS time list** (`VsRemixMenu.asm change_time_options`, `:856-940`): 1, 2, 3, 5, 8, 10, 12, 15, 20, 30, 60, 99, infinite.
- **Smashketball type** (`css.enable_toggling_mode_`, hooks 0x8013537C, 0x80135400, 0x801354A4): the Free-for-all/Team button flips
  the type (header "Smashketball 1/2") and the routine returns before the blue channel, the shades, the gates and the team select.
  `prevent_start_unless_two_teams_` refuses START unless exactly two teams are present among the panels in play.
- **Stock picker ranges** (`TwelveCharBattle.asm handle_stock_count_change_`): Tag Team 2..6 and Tug of War 1..25; every other mode
  1..99.
- **Tag Team queue** (`TagTeam.asm css`): up to 6 fighters per port (`character_queues`, `current_slot`). Picking, a costume change or a
  sync writes the panel fighter to the current slot (`update_slot_`); picking the token up advances the slot, A on a placed token advances
  and recalls, B with the token held empties the slot and goes back, a stock change clamps the slot, the recall takes 2 frames, and START
  is refused unless every port in play has a full queue. Six icons per panel at `x = panel x + 5 + 10 i`, y 117: an empty slot is the dot
  of file 0x19 (footer 0x80), a filled one the stock icon of the fighter (Master Hand 0.625).
- **Return to the VS menu** (`VsRemixMenu.asm set_cursor_index_`, `:810-848`): the VS menu reopens on page 2 with the cursor on the
  mode that was played.
- **Away mode** (`awayMode`, `:7031-7101`): with the second custom player tag named exactly `afk` the VS CSS presses START by itself
  after 120 ready frames, the denied FGM is muted and the results screen exits by itself.

### 2.7 Teams (`Teams.asm`)

A fourth team, yellow (team id 3), follows red 0, blue 1, green 2. Tables to extend: `team_button_table` (button image offset
0x1F648 in the CSS common file), `team_panel_table` (panel colour index, used by 5 patches: button press, screen load, FFA/Team
toggle, HMN/CPU button, controller plug), `team_port_color_table` (0x8013A6A0), `new_costume_table` and `add_team_costume`
(per-character yellow costume, `get_team_costume_` 0x800EC104), `classic_sonic_costume_fix_`, `team_shadow_colors` (0x8013B71C),
`team_name_table` with x, scale and palette tables for "YELLOW", `team_name_fgm_table` (results announcer), the series logo,
wallpaper and column colour indices of the results screen, and the winner loop bound (`slti at, s1, 3 + NUM_NEW_TEAMS`,
0x80137240). Three tables in other files get the yellow row by hand: `ComboMeter.team_offset_table`, `Shield.color_fix_.table_team`,
`Spawn.load_spawn_.valid_teams`. The team button is 5 pixels further right (0x22 to 0x27 in `CharacterSelectDebugMenu.asm:2076`
and `:2102`).

## 4. Port: structure

### 4.1 Data

`tools/gen_remix_css.py [path/to/smashremix-src]` reads `CharacterSelect.asm`, `Character.asm`, `FGM.asm` and `File.asm`, resolves the
symbolic constants (ids from `tools/gen_remix_roster.py`, so both generators agree) and writes `port/remix/remix_css_data.h`:
layout constants (`REMIX_CSS_NUM_*`, `START_*`, `PORTRAIT_*`, `BOOKEND_*`), `REMIX_CSS_PORTRAITS_FILE_ID` (0xA05),
`REMIX_CSS_IMAGES_FILE_ID` (0xA06), and arrays by Remix id: `kRemixCssSlotIds`, `kRemixCssBonusIds`, `kRemixCssPortraitX`,
`kRemixCssPortraitVelocity`, `kRemixCssPortraitOffset`, `kRemixCssNameOffset`, `kRemixCssLogoOffset`, `kRemixCssAnnounceFgm`,
`kRemixCssCircleSize`, `kRemixCssSelectionAction`, `kRemixCssPortraitId`. The script checks sentinel values (Mario portrait 0x1078,
the two bookends, Crash 0x2AE58 + 0x10, file ids). Rebuild the header after changing the generator; the textures themselves are the
reloc files already in the `.o2r` (`reloc_misc/file_2565` is 0xA05, `file_2566` is 0xA06).

Other data comes from the Remix RAM image through `remix_ram_image_*` and the generated `REMIX_SYM_*` symbols
(`tools/gen_remix_actions.py`): `Character.default_costume.table`, `Character.variants.table`, `Costumes.select_.num_costumes`,
`Costumes.extra_costumes_table`, `Teams.*`.

Remix ids equal port fkinds (`REMIX_ID_TO_PORT_FKIND(id) = id`): vanilla 0..26, Remix fighters 0x1D..0x60; 27 and 28 have no
fighter. The 12 vanilla `nFTKind*` constants are unchanged, so every `REGION_REMIX` branch indexes by fkind directly.

### 4.3 The four screens

The four CSS carry a `REGION_REMIX` branch next to the vanilla code (a build without `REGION_REMIX` compiles the vanilla logic).
`mnplayersvs.c` is the reference; the 1P, Training and Bonus screens use the same helpers and keep their own layout of names,
emblems and panels:

- File lists (`dMNPlayers*FileIDs`): `REMIX_CSS_PORTRAITS_FILE_ID` and `REMIX_CSS_IMAGES_FILE_ID` are appended (VS: indices 8 and
  11, with the results sprites file at 9 and the interface digits at 10 for the 12CB crown and stock cross; 1P game and Bonus:
  11 and 12; Training: 8 and 9).
- Portraits: `mn*MakeRemixPortrait` builds the 30 static sprites from file 0xA05 at scale `REMIX_CSS_PORTRAIT_SCALE`; the vanilla
  wallpaper, lock shadow and cross are not created. `mnPlayersVSMakeRemixPortrait` attaches the slide-in. The 12-entry vanilla
  tables (`portrait_pos_x`, `fkinds`, `portraits`, `announce_names`, spotlight `sizes[]`, fire wallpaper positions) stay on the
  vanilla path only.
- Fighter model: `ftManagerSetupFilesAllKind(fkind)` before `ftManagerMakeFighter`, so a Remix fighter's files load on first hover
  (the port has no alternate req list). `mnCharacters...` keeps its own copy of this call.
- Names and logos: `mn*MakeRemixNameAndEmblem` reads `kRemixCssNameOffset`/`kRemixCssLogoOffset`; offset 0 draws nothing, and the
  previous fighter's sprite is removed first on Training. Positions stay the vanilla ones of each screen.
- Hit tests and token: `mn*GetRemixPuckFighterKind` (cell hit test through `mnRemixCssSlotAtPoint`, crossed/locked check, then
  `mnRemixVariantGetFighterKind(player, fkind)`), `CenterPuckInPortrait` and `PuckAdjustPortraitEdge` use the 24x24 cells.
  `mn/mnplayers/mnremixcsstoken.c` (rules in `mnremixcsstokenrules.c`) gives the four screens the Remix token: scale 0.8125, the
  held token at the hand +12/-10, the rest spots of the cells and bookends, the flash image, the cursor down to y 212; VS also
  pushes tokens apart by portrait (variants of one portrait) with radius 10, and the 1P and Bonus tokens do not drift.
- Costume and shade: the shade lives in the slot struct on VS and in a file static (`sMNPlayers1PGameShade`,
  `sMNPlayers1PBonusShade`, `sMNPlayers1PTrainingShade[]`) on the other screens; it is reset when the hovered fighter changes and
  on select. The C-button costume uses `mnRemixCostumeApplyButton`; the "costume used" denial is dropped under Remix.
- Spotlight, announcer, selection action: `mnRemixCssGetSpotlightScale`, `kRemixCssAnnounceFgm` (0 or out of range plays nothing),
  `mnRemixCssGetSelectionStatus`. The vanilla `port_fighter_css_spotlight_scale` fallback remains for out-of-range fkinds.
- Records: `GMCOMMON_FIGHTERS_SAVE_NUM` is 97 under `REGION_REMIX`; the Bonus screen returns 0/FALSE for the `spgame_records` of
  Remix fkinds (the 12-entry array). The totals of the 1P CSS (`extend_1p_tally_`) and of the Bonus CSS (`extend_btx_tally_`, which
  skips ids whose Break the Targets stage is 0xFF) loop over every Remix id.
- Menu music: `gmRemixMenuMusicPlay(BattleSelect, FALSE)` on entry and `gmRemixMenuMusicStop()` on the back paths, see
  `docs/remix/menus.md`.

### 4.4 Costumes, variants, random (VS and Bonus)

- `mnPlayersVSUpdateCostume` uses `mnRemixCostumeApplyButton`: C right/left through `ftRemixPartImageGetNext/PrevCostume` (skips
  ids, includes extra costumes, wraps), C up/down the shade; `mnRemixCostumeGetRandomLegal` rerolls (at most 64 tries, then 0) until
  `ftRemixPartImageIsLegalRandomCostume`. `mnRemixCostumeApplyPartImage` runs every frame on the panel fighter (idempotent, returns
  after three reads for a vanilla costume), so it covers every `ftParamInitAllParts` call.
- C buttons in a team battle: `mnRemixCssCostumeButtonsActive`; `cpu_costumes_` is `mnPlayersVSGetCostumeButtonPanel` (VS).
- Variants: `mnRemixVariantHandleInput` in the cursor update, `mnRemixCssIndicatorsUpdate` from the frame update of the four
  screens draws the D-pad, icons, mark and J/E flag.
- Random: the L trigger (setting `'L' Selects Random Character`), the CPU pick and the Random bookend all go through
  `mnRemixRandomPickFighterKind`; the recent-randoms list is per port and survives the session. The bonus bookend (`mnremixcssbonus.c`)
  scrolls with Z/R and adds the bonus fighters to the pool when Random Select is not Default.
- The bonus fighters, the Random bookend and the slide-in exist on the four screens (1P and Training since lot 5: the `?` token rolls
  its fighter when the screen is left and comes back as `?`).

### 4.5 Modes

- Header and announcer: `mnPlayersVSGetModeHeaderOffset` (`mnRemixCssModeTitleOffset`), `mnRemixCssModeAnnounce` (called first in the
  entry voice block of `mnPlayersVSFuncStart`; a finished 12CB returns FALSE and the vanilla voice plays). The results screen uses
  the same offsets (`mnvsresults.c`).
- Goal picker: `mnRemixGoalPickerImageOffset` in `mnPlayersVSMakeTimeSelect`, press branch `mnPlayersVSCheckPickerPress` /
  `mnPlayersVSTogglePicker` (after the two arrows, before the game mode button), reset in `mnPlayersVSInitVars`, settle at the top of
  `mnPlayersVSSetSceneData` (the Time chosen becomes the VS menu time through `gmRemixModeGetVsTime/SetVsTime`). The picker zone is
  x + 16 .. x + width - 16 of the image and the arrow wins where they overlap. The time list of the VS menu (1..99, infinite) goes
  through `mnRemixGoalPicker*`.
- Smashketball: `mnPlayersVSUpdateGameMode` flips the type through `remix_modes_smashketball_set_type` (the CVar
  `gRemix.Modes.SmashketballType` that the port menu edits; `SSB64_SMASH_TYPE` overrides both), keeps the blue channel of the
  sprite file as the asm does, and `mnPlayersVSCheckModeTeams` (in `mnPlayersVSCheckReady`) enforces the two-team rule; a panel
  counts when its kind is not N/A and a fighter is picked or hovered.
- Tag Team queue: `mnRemixTagTeamCssWrite` from the end of `mnPlayersVSUpdateFighter`, `mnPlayersVSSelectFighterPuck` and
  `mnPlayersVSUpdateCostume`; `mnPlayersVSSetCursorGrab` (no move while the token flies back); `mnPlayersVSTagTeamCursorButtons`
  (A and B rules); `mnPlayersVSMakeStockSelect` calls `mnRemixTagTeamCssStocksChanged`; `mnPlayersVSSelectFighter` recalls in 2
  frames; `mnPlayersVSCheckReady` -> `mnPlayersVSCheckTagTeamQueues`; `mnPlayersVSGetTagTeamStockCount` lowers the picker to the
  Manual count. The match reads the queues in `gmRemixTagTeamBuildQueues` (`gm/gmremixtagteam.c`): the CSS first pick starts the
  match, a Random token rolls like a Random slot, FFA keeps the CSS costume, teams the team costume and shade. The slots from 1 are
  mirrored to the CVars of the port menu (`remix_modes_tagteam_set_slot`, Remix > Tag Team) and a slot the menu changed after the
  CSS wrote it takes the menu value, so the menu works as a prefill. `mnremixtagteamcssicons.c`: 6 icons per panel at
  `x = 22 + 69 i + 5 + 10 k`, y 117; the slot being picked draws the panel fighter's stock sprite, the others read a private copy of
  the fighter main file (`lbRelocGetExternHeapFile`) because the CSS replaces the main file of the panel fighter during hover.
- Teams: see section 4.6.

## 5. Port: deviations from the asm

Not deviations but open gaps, tracked in `patch_audit.md`: the token size, follow offsets and cursor limit (MN-1, MN-3), the
overlap rule (MN-4), the white flash (MN-2) and the 12CB winner voice (MD-4).

- **Token centring** uses the cell centre (`cell + w/2 - 13`) instead of `START_X + 12`.
- **Overscan**: the port crops 10 units of overscan (`port/gui/PortMenu.cpp`, `.Overscan.Enabled`, default on), so a screenshot shows a
  sub-rectangle of the 320x240 frame: `px_x = (u_x - 10) * 4.267`, `px_y = (u_y - 10) * 4.364` for a 1280x960 capture.
- **Model loading** is not the alternate req list; heap preloading and custom heap slots are not needed with a host heap.
- **Settings shortcut** (hold L on the CSS or stage select opens the Remix settings): replaced by the port menu.
- **Tag Team**: the icon palette of an FFA slot does not shift for a duplicate fighter of an earlier port; a Random-token slot shows the
  dot unless the `?` fighter has a stock sprite; `current_slot` is not re-read from the queue when the CSS opens; the menu names only
  the 30 grid fighters (any other reads as Random there).
- **Goal picker**: the asm checks the picker press before the other buttons; the port checks it after the arrows. The tap branch makes
  "no fast cycling" automatic.
- **Smashketball type** after a toggle keeps the blue channel of the sprite file, as the asm does.
- **12CB**: the Custom set is edited by the same inputs. The overlay text
  (Kabel) is above the game, the sprites are game objects; no text sits under a sprite. `TKOs` is a string in the asm that nothing
  draws.
- **Teams**: `sys/netreplay.c` still uses the vanilla `dIFCommonPlayerTeamColorIDs` (netplay replays); the results `x_teams` table has
  three entries and the Remix does not patch the team branch, so yellow reads the next array (175.0) like the asm.
  The Tag Team team costume uses `data->team`, not the port colour.
- **Default shield**: Shield option Default now follows `Shield.asm _teams_check` (team colour in a VS team battle, black for a CPU,
  port colour otherwise), so Default shields change colour in every match, as in the Remix.
- **Panel menu** details are in `docs/remix/panel.md`.

## 6. Port: the vanilla path the Remix branches bypass

The VS CSS keeps 12-entry tables on its non-Remix path: `portrait_pos_x[12]`/`portrait_vel[12]` (x 25, 70, 115, 160, 205, 250 per row),
`fkinds[12]` (no bound check), `portraits[12]` (PORT guard returning 0), `emblem_offsets[12]`/`name_offsets[12]` (no size guard),
`announce_names[12]`, spotlight `sizes[12]`, and the hit test `pos_x = puck.x + 13`, `pos_y = puck.y + 12`, `column = (pos_x - 25) / 45`
(rows for `35 < y < 79` and `78 < y < 122`). The same pattern exists in `mnplayers1pgame.c`, `mnplayers1ptraining.c` and
`mnplayers1pbonus.c`; `docs/remix/fighters.md` lists the sites. Status buffers `sMNPlayersVSForceStatusBuffer[64]` and
`sMNPlayersVSStatusBuffer[256]` were enlarged because of a synthetic fighter.
