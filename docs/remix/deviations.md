# Fighters and items: implementation map and deviations

Covers every Smash Remix 2.0.1 fighter (ids 0x1B to 0x60) and custom item (kinds 0x2D to 0x4B) of the port: which asm
scope became which C module, and where the port deliberately differs from the asm. Code lives in
`decomp/src/ft/ftremix/` (fighters, one directory per fighter with special-move code), `decomp/src/it/itremix/` (items),
`decomp/src/wp/wpmario/wpmarioremixfireball.c` (Mario-family projectile clones) and the vanilla hook sites listed in section 4.
The asm source is `.toolchain/pkgs/smashremix-src/src`. Tests: section 6 (`.claude/skills/remix-smoke-tests/`, `tests/remix/`).
Audit ledger (every item closed): `docs/remix/patch_audit.md`, groups g4 to g7.

A deviation is a conscious different implementation (different data layout, different state home, a different but equivalent
call, or a value the port picks where the asm reads an undefined register). A missing feature is a gap and is not listed here.

## 1. How a Remix fighter exists in the port

| Concept | Port implementation |
|---|---|
| Identity | The port fkind is the Remix id (`REMIX_ID_TO_PORT_FKIND(id) == id`, `port/remix/remix_roster_data.h`). Vanilla fighters keep 0 to 26; Remix ids start at 0x1B (RANDOM, the "?" model of the CSS Random bookend, never fought) and 0x1C stays unregistered so `nFTKindNull` (28) never names a fighter. |
| Roster | `tools/gen_remix_roster.py` generates `remix_roster_data.h` from `Character.asm` and the costume files. `port/remix/remix_roster.cpp` loads the `remix/fighters` blob and registers each id as a synth fighter. |
| Parent | Each synth clones its vanilla parent's `FTData` (`port_fighter_synth_ft_create`) and copies the parent's `FighterDescriptor` (`parent_fkind`), then replaces the fields the Remix record supplies. Vanilla tables indexed by fkind (Kirby `copy[]`, thrown rows, effect scale, shield rows, entry) are read through `port_fighter_parent_fkind`. The parent is always a vanilla fighter (Remix `define_character` parent column). |
| Specials | `ftRemixBindSpecials` (`ftremixbind.c`) turns the Remix action array (statuses `0xDC + i`) into the synth's `FTStatusDesc` table and special entry handlers. A routine address resolves to a decomp function (`ftremixvanillaprocs.c`, generated by `tools/gen_remix_actions.py`) or to a C port (`ftremixported.c`, generated by `tools/gen_remix_ported.py`). An address without a port falls back to the parent's routine for the same slot (the count is logged). |
| Hooks into vanilla | Remix patches vanilla routines with `OS.patch_start`. The port inserts calls to `ftRemix*` helpers at the vanilla function that contains the patched RAM address, under `#ifdef REGION_REMIX`. Each helper tests the fkind itself and is a no-op for others (`ftremixhooks.h`). |
| Remix id checks | Code inside shared routines compares `fp->fkind` with `REMIX_ID_*`. Polygon variants and clones that point at the same Remix routine addresses run the same C port. |

## 2. Fighter map

Remix-specific code beyond the shared patches of section 4. Polygon variants (`N*`, 0x4D to 0x60) bind the action array of their base fighter, so
they run the base fighter's C ports (entry statuses: 5.4). Vanilla polygon fighters (0x0E to 0x19) get their `o_attributes` patched from the Remix
blob by `remix_roster_load` (`port_fighter_set_attributes_offset`, `ftport.c`), because Remix rebuilt those main files with the attributes block at
a new offset.

## 5. Deviations

### 5.1 Representation (all fighters and items)

- **LP64 scratch words.** Remix routines use FTStruct words by N64 offset (`sw t0, 0x0B18(a0)`). `ftRemixFighterWord` / `ftRemixFighterFloat` /
  `ftRemixFighterKirbyHat` (`ftremixfields.c`) map 0x0ADC to 0x0B13 onto `passive_vars`, 0x0B18 to 0x0B4B onto `status_vars` and 0x0980 onto
  `modelpart_status[2]`, keeping each word's position inside its union so routines that share a word still share it. An unmapped offset logs
  and exits. Raw `(u8 *)fp + off` writes would hit unrelated fields.
- **Pointer-valued words** do not fit the 32-bit word and live in a per-player static: `sFTRemixSonicNSPTarget`, `sFTRemixCrashDigEndPos`,
  `sFTRemixMewtwoUSPMoveTics` / `sFTRemixMewtwoUSPMoveAngle`.
- **Overlay structs** pinned by `_Static_assert` hold state the asm keeps at fixed N64 offsets: `MewtwoShadowBallVars` over
  `wpSamusWeaponVarsChargeShot`, `FTRemixGoemonRyoVars` and `FTRemixSonicUSPSpring` over `weapon_vars`, `FTRemixGoemonChargeVars` over
  `status_vars`, `ITRemix<Name>Vars` over `item_vars`. The Ryo therefore no longer writes `attack_pos[1]` (only the Ryo reads those words).
- **WPStruct offsets.** The generated layout (`struct_offsets.txt`) is 4 bytes low on WPStruct from 0x25C: N64 0x264 is `group_id` and 0x268 is
  `lifetime` (`wpMainDecLifeCheckExpire` reads 0x268). Conker nut, Lanky grape, Sheik needle and Goemon Ryo write `wp->lifetime`.
- **ITStruct offsets** are also off from about 0x248, so item ports map each asm access by meaning to a named field: 0x2CE mask 0xCF
  `times_landed`, 0x33E `multi`, 0x398 `proc_dead`, 0x2D3 bit 4 `is_unused_item_bool`, 0x158 bit 0x10 `attack_coll.can_rehit_shield`, 0x340 high
  nibble `event_id`, 0x2C0 `lifetime` / `vel_scale`, 0x348 `arrow_gobj` (the table says 0x344). Remix-only slots (0x1C4 to 0x1D4, 0x354) sit
  in `ITRemix<Name>Vars`.
- **Constants in vanilla RAM.** `remix_ram_image_read_word` only reaches the Remix image (base 0x80400000). Floats the asm loads from vanilla
  overlay addresses cannot be read: the Golden Gun tilt (`itRemixGoldenGunRollTilt` keeps only the RNG advance, so the random sequence is
  unchanged), the Metallic Bee laser clamp (`GRREMIX_METALLIC_LASER_SCALE_MAX` assumes the Fox blaster clamp `WPBLASTER_CLAMP_SCALE_X`),
  Blue Shell's recoil and rotation constants (from the red shell), Marina's throw-turn rotation and Marth's DSP facing rotation (written as
  degrees; `MARTH_DSP_FACING_ROTATION` is assumed to be 90).
- **Hex over comments.** Where an asm comment and the immediate disagree the port uses the immediate (Wolf up special speeds, Conker and
  Flashbang ground drag 0.9375, Basketball divisor and max speed, Boomerang 70.0 for Young Link).
- **Undefined register reads.** Where the asm uses a register no instruction set (a stale `v1`, `s0`, `a1` or `a3`) the port implements the
  evident intent: `ftCommonDamageGetKnockbackAngle(angle, ip->ga, knockback)` (Basketball, Conker grenade, Flashbang, Gordo, Waddle Dee), the
  item's own `DObj` where `s0` is unset (Cloud, Gem, Gordo, Waddle Dee, Boomerang), the hit-refresh timer stored in `item_vars` (Shuriken),
  `efManagerFlameRandgcMakeEffect` with position only. Sequences that mask a never-loaded register (`and v1, v1, 0x07; sb v1, 0x18D(a0)` in
  Marina, Mewtwo, Dragon King) clear `is_absorb`, `absorb_lr`, `is_goto_attack100` and `is_fastfall` explicitly (Goemon clears `is_fastfall` only).
- **Math and rounding.** `sinf`, `cosf`, `atan2f`, `sqrtf` (or `syUtilsArcTan2`, `__cosf`, `__sinf`) replace the N64 routines, so the last float bit
  can differ. The asm's `cvt.w.s` rounds to nearest: the port uses `lrintf` in Flashbang, `(s32)(sqrtf(x) + 0.5F)` for stick magnitudes
  (identical), and truncating casts in Basketball (fire damage, angle, percent halving, anim timer) and Gordo (`speed_int`).
- **Unported routines fall back** to the parent's routine for that slot (`ftRemixBindSpecials`), which keeps the match alive.
- **Special dispatch.** The asm per-id special tables (`Character.*_nsp/usp/dsp`, air and ground) are replaced by `port_fighter_special_handler`
  (`ftcommonspecialn.c`, `ftcommonspecialair.c`, `ftcommonspecialhi.c`, `ftcommonspeciallw.c`) with the Remix actions bound by `ftRemixBindSpecials`.
  Segment sizes and file-pointer loops over `NUM_CHARACTERS` are loops over registered fkinds (`ftmanager.c`); `move_action_array_table_` is
  read from the Remix image (`REMIX_ACTION_ARRAY_TABLE`); per-id script tables and FGMs live in the `FighterDescriptor`; `menu_zoom_patches`
  are `port_fighter_scale` from `remix_roster.cpp`.
- **Moveset parser.** `ftMainParseMotionEvent` ends the script when `LoopEnd` runs with `script_id < 2` (`#ifdef PORT`): the N64 indexes
  `loop_count[-2]` (aliasing other fields) and the script ends, while the LP64 layout would loop forever (Mewtwo `USP_END.bin`).
- **Loader.** `lbreloc_bridge.cpp` nulls an out-of-range extern chain slot and keeps walking (Peach turnip file 5144 lists two unused images past
  its end). `chain_fixup_vertex` (`port/bridge/lbreloc_byteswap.cpp`) stops at the first vertex that is a sync/end command with no argument bits,
  so a `G_VTX` that asks for more vertices than its array holds does not rotate the display list Remix packs behind it (Kirby hat files).

### 5.2 Fighters

- **Bowser** (`bowser/ftremixbowser.c`). The flame is the vanilla Fire Flower flame weapon (`itFFlowerWeaponFlameMakeWeapon`). Bowser's ammo
  (asm halfword 0x0ADE) is the passive word of `ftRemixBowserAmmoWord`; Kirby's copy keeps its ammo at 0x0AE0. The first-frame sparkle the
  asm sets is overwritten before its only call, so only the dust plays, like the ROM.

### 5.3 Shared patches and engine behaviours

- **Thrown rows.** `ftcommonthrow.c` clamps a synth victim to Mario's row of the thrower's `thrown_status[]` table (`catch_vk`), because
  the table is indexed by the victim's fkind but sized for vanilla fkinds. The asm tables use the victim's parent id
  (`f_thrown_action_fix_`, `b_thrown_action_fix_`); victims whose parent is Yoshi, Kirby, Jigglypuff or Donkey Kong may react differently.
  `thrown_redirect_fix_` uses `port_fighter_parent_fkind` (`ftmain.c`).
- **Custom grab actions.** `capture_action_override_` and `capture_position_fix_` go through `port_fighter_custom_capture_action`
  (Wario, Piano registered in `ftremixdeschooks.c`) in `ftcommoncapturepulled.c`; the frame-1 call to 0x8014AB64 is not compared.
- **Shield damage flash.** `is_damage_shield` (`ftremixshield.c`) keeps the vanilla colour for the shield's damage flash; the asm recolours it.
- **Mario fireball clones.** The capsule palette is rolled once at spawn (`wpmariofireball.c`, `wpmarioremixfireball.c`), where the asm
  rolls on every accessory tick with temp 1 set; Dr. Luigi is found from the owner or copy id (`REMIX_ID_DRL`) and the hat-based
  palette range is applied to the spawned weapon; capsule hits swap `dEFManagerDamageNormalLightIDs[0]` to 0x81/0x97
  (`wpRemixMarioFireballCapsuleHitGfx`).
- **Damage.** `plunge_main_` caps `physics.vel_air.y` (the asm caps `coll_data.pos_diff.y`); the plunge never exceeds -50, so no visible effect.
- **GFX ids.** `lbRemixGfxIsNewEffect` replaces the 0x6669B size check; the extended script and texture maps are grown arrays
  (`lb/lbremixgfx.c`, 33 scripts, 9 texture blocks). Hook sites `lbRemixGfxTakeScriptOverride` and `lbRemixGfxPrepareEffect`.
- **Size effects set once.** Link's up special projectile and gfx scale (`ftRemixSizeScaleLinkWeapon`, `ftRemixSizeScaleLinkEffect`) are set
  at spawn where the asm rewrites them every render; the Dragon King ball scale is applied per update (`ftRemixDragonKingNSPApplyBallScale`)
  instead of per render. Identical while the multiplier does not change mid-move.
- **Menus.** Item menu entries and HUD name sprites (`sc1ptrainingmode.c`, kinds 0x2D to 0x39), the VS item switch pages
  (`mnvsitemswitch.c`: R flips page, L toggles the current page from that page's first row; the asm L flips from vanilla row 1 and sets all
  15 vanilla and 13 custom values) are adapted to the port's menu code.
- **Item frequency and Pokemon voices.** `mnVSItemSwitchSetItemToggles` keeps `item_appearance_rate` even with every toggle off
  (`always_update_item_frequency_`); RANDOM Pokemon voice mode reads `syUtilsRandSeed()` where the asm reads RAM 0x800A0578 (not verified to be the same word).
- **Scene change item clear.** `itRemixClearActiveItems` runs on every scene change (a superset of the asm's CSS/VS/Training/VS Results calls
  and of RTTF/BTT/BTP init).
- **Japanese item sounds.** `ftremixjapanesesounds.c` takes the item's owner from the spawning fighter (`ITEM_FLAG_PARENT_FIGHTER`) and no
  owner otherwise; the asm reads stack slot 0x20(sp) of `itManagerMakeItem`, which that function never writes (DEVIATION in code). Toggle
  Always and Never behave as in the asm.

### 5.4 Entry effects and polygon fighters

- **Clone entry effects.** A clone copies its parent's `entry_make_effect`, which switches on `fp->fkind` and does nothing for a Remix id.
  `ftremixentry.c` holds the effective table per synth id. The vanilla makers read their model from the vanilla fighter's file global, which is
  not loaded when only a clone is in the match, so each call points the vanilla `EFDesc` at the entering fighter and restores it afterwards. A
  clone that keeps the parent's effect uses the file slot (special1..4) holding the same file id as the vanilla effect's file; a Remix patch that
  swaps in its own struct is a row of `dFTRemixEntryOverrides` (`ftremixentrydata.c`: file slot, optional base effect, four offsets), covering
  `linkshared.asm`, `samusshared.asm`, `dkshared.asm` and `captainshared.asm`. With neither, the effect is skipped with a log line.
- **Captain car and Arwing joints.** `efManagerCaptainEntryCarMakeEffect` calls `ftRemixEntryGetCarAnim` and `efManagerFoxEntryArwingMakeEffect`
  calls `ftRemixEntryGetArwingAnim`, because the vanilla makers read animation joints from hard-coded offsets of the vanilla file. Wolf's
  Wolfen is a row whose flags word is the vanilla `EFDesc` packed (file `file_8`, setup offset 0x2610) with its own Arwing animation values
  (`dFTRemixEntryArwingAnims`).
- **Wolf's entry timing is authored data.** Wolf is visible and crouched while the Wolfen flies in (his `File.WOLF_APPEAR` animation hides on
  a different joint and lands about 6 frames before the Arwing arrives, which still follows Fox's timeline); the `Wolf.asm` comments say the
  offsets "need updating", so the mismatch probably exists in Remix. No port change.
- **Polygon entry statuses.** The polygon variants' entry status runs `ftCommonEntryNullProcUpdate` with no physics proc. Their Remix motion
  rows have flags 0 (no hidden joints), but the port merges the parent's hidden-joint flags into every synth row
  (`ftPortCopyMotionArray`, `ftPortParentHiddenJointFlags`) so parent routines never read a missing joint (the N64 reads RDRAM page zero).
  `ftMainSetStatus` therefore clears `is_use_xrotn_joint`, `is_use_transn_joint` and `is_use_yrotn_joint` for a status that runs
  `ftCommonEntryNullProcUpdate` with no physics proc (checked on 36 statuses of ids 0x4D to 0x5F). Without it the polygon crouches into the floor.
- **Sonic and Tails.** `dkshared.asm barrel_alternate` picks the right or left Tails struct by the fighter's facing; the port keys on
  `status_vars.common.entry.lr` (`nFTRemixEntryEffectDonkeyBarrelRight`) because `ftCommonAppearSetStatus` clears `fp->lr` first. The Super Sonic
  branch is dead (SSonic.asm skips the entry script).

### 5.5 Items

Conventions that apply to every item port:

- **Spawn failure.** When `itManagerMakeItem` returns NULL the asm returns the incoming `a3` (a velocity or flags value); the port returns NULL.
- **Descriptor.** The Remix `ITDesc` runs into the state table, so the procs at 0x14 to 0x30 are the procs of state 0 and every descriptor sets
  them. Transform types come from the asm word 0x0C (0x1B `TraRotRpyR`, 0x1C `TraRotRpyRSca`, 0x12 `Tra`); words that are not a valid matrix kind
  (0x1B000000) use the tomato defaults (`TraRotRpyR`, `Null`, 0).
- **Per-effect state.** Effects that Remix runs as `Render.register_routine` objects run as `GObjProcess`es: on the owning fighter (P-Wing
  priority 4, Franklin Badge 1) or on a routine GObj made with `gcMakeGObjSPAfter` on `nGCCommonLinkIDInterface` (Cloaking Device and
  Super/Poison Mushroom priority 3, Lightning `ITREMIX_LIGHTNING_PROCESS_PRIORITY`). The routine GObjs are deliberately not on the effect link,
  because `ftParamRunProcEffect` walks that link and reads every `user_data` as an `EFStruct`. The Super Mushroom pool has 16 slots; a full pool
  makes a pickup a no-op. The priorities have no asm basis. Cloaking Device and Lightning shrink timers are per port; Basketball keeps one
  `ITRemixBasketballVars` per ball in a slot pool (`sITRemixBasketballSlots`).
- **Shared minion layout.** Waddle Dee, Waddle Doo and Gordo share one Remix minion state machine and the `item_vars` prefix
  `ITRemixWaddleDeeVars` (pinned by `_Static_assert` in `itremixwaddledee.h` and `itremixgordo.c`); N64 0x33E is `ITStruct.multi`.
- **`proc_dead` results.** Blast-zone procs return TRUE (destroyed) for Robot Bee, Scuttle Minion, Banzai Bill and Gordo; Klap Trap and Car return
  FALSE (the asm jumps past the destroy test); Cloud's is a bare return kept in a private field; Turnip clears the slot.
- **Size.** Mushrooms and Lightning write Size through `ftRemixSizeSetMultiplier` (Remix writes `Size.multiplier_table`). The Lightning zap tests
  team state from `gSCManagerVSBattleState` (`is_team_battle`, `is_team_attack`) for the asm's `match_info` bytes and compares revive actions as
  Remix numeric ids 7 to 9, not as `nFTCommonStatusRebirth*`.
- **Dead code** (dead loads, stack spills, commented-out branches, `_speed_refresh`) is not ported. Items given by Start With, Taunt Item and the
  Peach pull spawn without the swirl (`ftremixstartitem.c`).

## 6. Tests

- Headless unit tests of the pure rules (Blue Shell first-place rules, Stopwatch background, Sonic classic, Smashketball and others):
  `cmake --build <build> --target run_remix_mode_tests` (`tests/remix/`).
- Fighter specials in a real match, headless: `.claude/skills/remix-smoke-tests/scripts/vs.sh <fkinds> <input> <name> [frames]` with
  `inputs/nsp_tap.txt`, `dsp_tap.txt`; `special_matrix.sh <fkind>...` runs NSP/DSP/USP against Kirby and greps the log for
  abort/assert/fatal; `parallel.sh <jobs> matrix <fkinds...>` runs it in parallel. `SSB64_VS_FKINDS=a,b[,c,d]` selects fighters (decimal
  fkinds; vanilla 0..26, Remix 0x1D..0x60), `SSB64_VS_STAGE=<gkind>` the stage, `SSB64_INPUT_SCRIPT` drives P1.
- Attract demo pairs: `SSB64_START_SCENE=61 SSB64_DEMO_FKINDS=a,b`.
- Kirby copy: `SSB64_REMIX_KIRBY_COPY_TEST=<fkind>` with `vs.sh 8,<fkind> inputs/nsp_kirby.txt` (the copied fighter must be in the match, because
  its weapon and item files only load for present fighters; copy at frame ~405, not earlier).
