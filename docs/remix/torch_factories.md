# Smash Remix: Torch factories (`SSB64:REMIXFIGHTERS`, `SSB64:REMIXAUDIO`, `SSB64:REMIXBLOB`)

Covers the Torch factories that read `baserom.remix.z64` and write the Remix-only resources into the o2r, and the byte contract the port reads.
Code: `torch/src/factories/ssb64/` (registered in `torch/src/Companion.cpp`, inside `SSB64_SUPPORT`) and the yamls in `yamls/remix/`. Torch selects
`yamls/remix` by the SHA-1 of the ROM (`config.yml`). The ROM-derived data lives only in the `.o2r` and in `build/`.
Test: `tools/test_remix_blobs.py` (commands under "Verification").
Open gaps: `docs/remix/patch_audit.md`.

## Files

| File | Responsibility |
|---|---|
| `RemixRom.{h,cpp}` | Remix ROM detection (country `E`, size above 0x1000000), bounded big-endian reads, RAM to ROM translation |
| `RemixFighterTable.{h,cpp}` | Reads the FTData struct table (ROM `0x92610`) and the motion and menu arrays |
| `RemixFightersFactory.{h,cpp}` | `SSB64:REMIXFIGHTERS`: serializes the `remix/fighters` format |
| `RemixAudioCtl.{h,cpp}` | Runtime image of a ctl (vanilla blob + code image + zeros) and the reach scan that sizes the TBL |
| `RemixAudioFactory.{h,cpp}` | `SSB64:REMIXAUDIO` (parameter `bank`): the eight audio banks (five ctl/tbl/sbk, three FGM) |
| `RemixBlobFactory.{h,cpp}` | `SSB64:REMIXBLOB` (parameters `offset`, `size`): a raw ROM range read as a ROM file offset, never as a segmented address |

The factories derive from `BlobFactory` and reuse `BlobHeaderExporter`, `BlobBinaryExporter` and `BlobCodeExporter`, so each output is a standard BLOB
resource: the 0x40 byte Torch header, a u32 size, then the payload.

Yamls in `yamls/remix/`:

- `audio.yml`: `SSB64:REMIXAUDIO` entries with a `bank` (`B1_sounds1_ctl/tbl`, `B1_sounds2_ctl/tbl`, `S1_music_sbk`, `fgm_unk`, `fgm_tbl`, `fgm_ucd`).
  The `fgm_*` entries are rebuilt as described in `docs/remix/audio_extraction.md`.
- `remix.yml`: `fighters` (`SSB64:REMIXFIGHTERS`) and `ram_image` (`SSB64:REMIXBLOB`, ROM `0x2C00000`, size `0x400000`). The resource name is
  `<yaml path under yamls/remix without extension>/<key>`, so the o2r holds `remix/fighters` and `remix/ram_image`.
- `particles.yml`: the particle script and texture banks as `SSB64:REMIXBLOB` entries (`particles/<name>`).

## Formats

**`remix/fighters`** (little-endian): 16 byte header (`'RMXF'`, version 1, count 97, reserved 0), 97 records of 0x80 bytes, then the motion arrays (12 bytes
each: anim_file_id, command_offset, flags). `mainmotion_off` and `menu_off` are byte offsets from the start of the motion region (right after the
records). For an empty array the recorded offset is the current end of the motion region, on both sides (Torch and the reference test).

**`audio/*`**: runtime image of the ctl (RAM base `0x800472D0` for music, `0x8004D9F0` for SFX), the TBL as a contiguous ROM slice up to the last
reachable sample, the SBK as a ROM slice from `0x2504750`, and the compact FGM tables. Details and numbers: `docs/remix/audio_extraction.md`.

**`remix/ram_image`**: the 4 MiB Remix code and data image (the boot DMA of `Boot.asm`), kept as is. The port (`port/remix/remix_ram_image.cpp`) reads
Remix tables and motion scripts addressed by raw `0x804xxxxx` pointers from it.

## Verification

```
.toolchain/host/cmake/CMake.app/Contents/bin/cmake -S torch -B build-torch   # sources are globbed, no network needed
.toolchain/host/cmake/CMake.app/Contents/bin/cmake --build build-torch -j 4
./build-torch/torch o2r baserom.remix.z64 -s $PWD -d build/remix-test/run1
.toolchain/host/venv/bin/python -I tools/test_remix_blobs.py --o2r build/remix-test/run1/BattleShip.o2r
```

The test checks that every payload is byte-identical to its reference: the audio blobs to `tools/remix_dump_audio.py` (regenerated into
`build/remix-dump/audio` on each run), `remix/fighters` to a Python reference built from the JSON of `tools/remix_dump_fighters.py`, and the
`SSB64:REMIXBLOB` entries to the raw ROM range. A changed byte in the o2r fails the test at the first differing position with exit status 1.

## Design decisions

- **TBL size.** `FindRemixSampleExtent` walks the ctl from the bank file with the same bounds rules as `BankParser` (`port/bridge/audio_bridge.cpp`).
  Only the wavetable reach enters the computation, so envelopes, keymaps, books and loops are not copied into that count. The result matches
  the Python reference byte for byte.
- **ROM guard.** `RequireRemixRom` refuses any ROM that is not country `E` with a size above 0x1000000. It also checks the music ctl bank pointer and the
  0x177 count of the SBK. These yamls are processed only with the Remix ROM (`config.yml` picks `yamls/remix` by hash).
- **Action arrays** are not part of `remix/fighters`: the port takes the Remix action layout from `port/remix/remix_action_layout.h` (generated by
  `tools/gen_remix_actions.py` from the assembled Remix build) and the RAM image. The action array count is not stored in the struct (see
  `docs/remix/fighter_table_extraction.md`, caveat 1).
- The port loads `remix/fighters` with `remix_roster_load()` (`docs/remix/roster_loader.md`) and the audio blobs with `port/bridge/audio_bridge.cpp`.

## Blob contract

All integers are **little-endian** (the blob is read by port code, not by the N64 game).

#### `remix/fighters` (BLOB resource in the `.o2r`)

```
Header (16 B): u32 magic = 'RMXF' (0x46584D52), u32 version = 1, u32 count (= 97), u32 reserved = 0
Records: count x 0x80 B, in struct table order (index = Remix id)
  +0x00 u32 remix_id
  +0x04 u32 file_ids[9]        // main, mainmotion, submotion, model, shieldpose, special1..4 (same order as FTData)
  +0x28 u32 file_main_size
  +0x2C u32 o_attributes
  +0x30 u32 file_anim_size
  +0x34 u32 mainmotion_count
  +0x38 u32 mainmotion_off     // byte offset from the start of the FTMotionDesc[] region
  +0x3C u32 menu_count
  +0x40 u32 menu_off           // same
  +0x44.. reserved (zeros) up to 0x80
After the records: FTMotionDesc arrays, 12 B each: u32 anim_file_id, u32 command_offset, u32 flags
```

`FTMotionDesc` = `{ anim_file_id, offset, flags }` of the decomp (`decomp/src/ft/fttypes.h`); in the ROM the three fields are big-endian and Torch converts
them to little-endian. `menu_*` is the decomp `submotion` array. Source of the data: the struct table at ROM `0x92610` (97 RAM pointers to 0x78 B
structs). RAM to ROM translation: `RAM - 0x80084800` (vanilla data), `RAM - 0x7D800000` (expanded segment `0x80400000+`), `RAM - 0x80288A20` (overlay
window `0x80390000..0x80400000`). Reference: `tools/remix_dump_fighters.py` (`docs/remix/fighter_table_extraction.md`).

#### `audio/*` (BLOBs)

`audio/B1_sounds1_ctl`, `audio/B1_sounds1_tbl`, `audio/B1_sounds2_ctl`, `audio/B1_sounds2_tbl`, `audio/S1_music_sbk`, `audio/fgm_unk`, `audio/fgm_tbl`,
`audio/fgm_ucd`: the files rebuilt by `tools/remix_dump_audio.py` (ctl = RAM image: vanilla blob first, code image at `RAM - 0x7D800000`, zeros between), so
`audio_bridge.cpp` reads the same names as for the vanilla game. The other `fgm_*` and `particles` segments of the US yamls are plain segments.

### Data that comes from the Remix source (not the ROM)

`port/remix/remix_roster_data.h`: per fighter, `remix_id`, name, `parent` (vanilla), `add_actions`, `num_costumes`, `variant_type`, `sound_type`, and more
(`docs/remix/roster_data.md`). Source: `.toolchain/pkgs/smashremix-src/src/Character.asm` (`define_character`) and `src/costumes/*.asm`.
